Project Specification & Work Plan

ระบบรับเลี้ยงสัตว์และจัดการศูนย์พักพิงสัตว์
Pet Adoption API (Supabase Backend)

เอกสารการแบ่งงาน 3 คนและมาตรฐานการทดสอบระบบ (อ้างอิงรูปแบบโปรเจกต์ cybersec-69)
ชื่อโครงการ Pet Adoption API
เทคโนโลยีหลัก Supabase (PostgreSQL, Auth, RLS, Storage)
จำนวนสมาชิกทีม 3 คน (DB Lead, Auth/Storage Lead, API/Testing Lead)
เครื่องมือทดสอบ api.http.simple (VS Code REST Client)

🎯 ภาพรวมและวัตถุประสงค์

โครงการนี้มีจุดมุ่งหมายในการพัฒนา Backend API สำหรับระบบ Pet Adoption (รับเลี้ยงสัตว์) เพื่อเชื่อมต่อระหว่างศูนย์พักพิงสัตว์ (Shelters) กับผู้ที่ต้องการรับเลี้ยงสัตว์ (Adopters) โดยใช้บริการคลาวด์และฐานข้อมูลสมัยใหม่ของ Supabase ครอบคลุมการยืนยันตัวตน, จัดการรูปถ่ายสัตว์เลี้ยง, การยื่นคำขอรับเลี้ยง และการคัดกรองคุณสมบัติ พร้อมกำหนดการแบ่งงานในทีม 3 คนอย่างเป็นระบบ

📌 ผลสัมฤทธิ์ที่ส่งมอบ (Key Deliverables)

  • ฐานข้อมูล Supabase PostgreSQL ประกอบด้วย 5 ตารางหลัก พร้อม Trigger อัตโนมัติและ RLS Security Policies
  • ระบบ Supabase Authentication รองรับ 3 บทบาท (ADMIN, SHELTER_STAFF, ADOPTER)
  • Storage Bucket (pet-images) สำหรับจัดเก็บภาพถ่ายสัตว์เลี้ยงแบบ CDN เข้าถึงได้สาธารณะ
  • ชุดทดสอบครบวงจรผ่านไฟล์ api.http.simple ในรูปแบบมาตรฐานเดียวกับ cybersec-69
จัดทำโดย: ทีมพัฒนาประจำโครงการ Pet Adoption API | รูปแบบการบริหารจัดการ: มาตรฐาน cybersec-69

1. การแบ่งหน้าที่ในทีม 3 คน (Team Roles & Responsibilities)

สมาชิก บทบาท / ตำแหน่ง Branch ที่รับผิดชอบ ชิ้นงานหลักที่ส่งมอบ (Deliverables)
คนที่ 1 Database & Supabase Lead
(ดูแลโครงสร้างข้อมูลและสคริปต์)		 feat/supabase-db • ออกแบบ ERD และความสัมพันธ์ข้อมูล
• ไฟล์ supabase/schema.sql (Tables, Enums, Triggers, RLS)
• ไฟล์ supabase/seed.sql และ seed.ts (ข้อมูลจำลองสัตว์เลี้ยงและหมวดหมู่)
• ไฟล์คอนฟิกสิ่งแวดล้อม .env.simple และ .env.example
คนที่ 2 Auth, Security & Storage Lead
(ดูแลระบบล็อกอินและความปลอดภัย)		 feat/supabase-auth-storage • เชื่อมต่อ Supabase Auth Client (SDK / GoTrue)
• เขียน Middleware ถอดรหัส JWT และ Role Guard (`ADMIN`, `STAFF`, `ADOPTER`)
• สร้าง Auth Endpoints (`/admin/login`, `/api/auth/...`, `/api/users/me`)
• ตั้งค่า Supabase Storage Bucket (`pet-images`) และ RLS Policy อัปโหลดรูปภาพ
คนที่ 3 REST API & Testing Lead
(ดูแล CRUD & ไฟล์ทดสอบ)		 feat/api-testing • CRUD Endpoints สำหรับ Categories, Pets, และ Adoption Applications
• Business Logic (ตรวจสอบสถานะสัตว์ และอัปเดตสถานะเมื่อคำขอได้รับการอนุมัติ)
• ไฟล์ทดสอบ api.http.simple ครบทั้ง Admin, User, Content
• ตรวจสอบผลลัพธ์การยิง API และเขียนคู่มือการทดสอบ

ลำดับขั้นตอนการส่งต่องาน (Handover Timeline)

  1. ระยะที่ 1 (คนที่ 1 เริ่มต้น): แตก Branch feat/supabase-db → เขียน SQL Schema และ Seed Data บน Supabase → ทดสอบ Schema ผ่าน Supabase Table Editor → Merge เข้าสู่ main
  2. ระยะที่ 2 (คนที่ 2 รับไม้ต่อ): ดึงโค้ดล่าสุดจาก main → แตก Branch feat/supabase-auth-storage → พัฒนาระบบ Authentication, Token Verification และระบบ Storage รูปภาพ → Merge เข้าสู่ main
  3. ระยะที่ 3 (คนที่ 3 ดำเนินการสมบูรณ์): ดึงโค้ดล่าสุดจาก main → แตก Branch feat/api-testing → จัดทำ Routes จัดการข้อมูลสัตว์เลี้ยงและคำขอรับเลี้ยง → จัดทำไฟล์ api.http.simple ทดสอบยิง Request ครบทุก Flow → ตรวจสอบความถูกต้องและ Merge เข้าสู่ main

2. โครงสร้างฐานข้อมูล (Database Schema)

ตาราง (Entity) คอลัมน์สำคัญ Constraints & ความสัมพันธ์ คำอธิบายหน้าที่
profiles id, email, first_name, last_name, role, phone PK -> auth.users(id)
Role: ADMIN, SHELTER_STAFF, ADOPTER		 ข้อมูลโปรไฟล์ผู้ใช้งาน ขยายจากตารางยืนยันตัวตนของ Supabase
categories id, name, description, icon_url PK UUID, Name Unique ชนิดของสัตว์ เช่น Dog, Cat, Rabbit, Bird
pets id, name, category_id, breed, age_months, gender, size, status, image_url FK -> categories(id)
Status: AVAILABLE, PENDING, ADOPTED		 รายการสัตว์เลี้ยงในศูนย์พักพิง มีข้อมูลสุขภาพและความพร้อมในการรับเลี้ยง
adoption_applications id, pet_id, applicant_id, status, living_condition, reason_for_adoption FK -> pets(id)
FK -> profiles(id)
Status: SUBMITTED, UNDER_REVIEW, APPROVED, REJECTED		 ใบสมัครขอรับเลี้ยงสัตว์ บันทึกสภาพแวดล้อมที่อยู่อาศัยและการพิจารณา
pet_inquiries id, pet_id, user_id, message FK -> pets(id)
FK -> profiles(id)		 คำถาม/ข้อความสอบถามเกี่ยวกับสัตว์เลี้ยงตัวนั้นๆ

3. แผนผังการทดสอบ API ด้วย api.http.simple

# โครงสร้างชุดทดสอบแบ่งเป็น 3 หมวดหมู่หลัก (ตามสไตล์ cybersec-69) 1. Admin ├── 1.1 Admin Login (POST /admin/login) └── 1.2 Admin Profile (GET /admin/users/me) 2. User (Adopter / Staff) ├── 2.1 User Register (POST /api/auth/register) ├── 2.2 User Login (POST /api/auth/login) ├── 2.3 User Forgot Password (POST /api/auth/forgot-password) └── 2.4 User Profile (GET /api/users/me) 3. Content ├── 3.1 Categories (GET all, POST create, PUT update, DELETE) ├── 3.2 Pets (GET all with filters, POST create, PUT update, DELETE, POST inquiries) └── 3.3 Adoption Applications (POST submit, GET my/all, PATCH review status)
