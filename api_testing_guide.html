สมาชิกคนที่ 3 : REST API & Testing Lead git: feat/api-testing

คู่มือการทดสอบระบบ Pet Adoption API ผ่าน VS Code REST Client

สถาปัตยกรรม REST API แบบแยก 3 บทบาท สไตล์ CyberSec-69 พร้อมชุดทดสอบ End-to-End ในไฟล์ api.http

🛠️ การเตรียมความพร้อมบนเครื่องก่อนเริ่มทดสอบ (ทำครั้งเดียว)
  1. สลับไปยัง Branch ของคนที่ 3: 
    git fetch origin
git checkout feat/api-testing
git pull origin feat/api-testing
  2. ติดตั้ง Extension ใน VS Code: ไปที่แท็บ Extensions (Ctrl + Shift + X) แล้วค้นหาติดตั้ง REST Client (ของผู้พัฒนา Huachao Mao)
  3. เปิดรันเซิร์ฟเวอร์ Express: 
    npm run dev
    *(สังเกตให้ขึ้นสถานะ: 🐾 Pet Adoption API server running at: http://localhost:9091 และอย่าเพิ่งปิดหน้าจอนี้)*
📊 สรุปโครงสร้างเส้นทาง API ทั้งหมดในระบบ
Method Endpoint สิทธิ์การเข้าถึง หน้าที่การทำงาน
POST /admin/login Public ล็อกอินบัญชีแอดมิน เพื่อรับ ADMIN_TOKEN
GET /admin/users/me ADMIN ดึงข้อมูลโปรไฟล์ผู้ดูแลระบบระดับสูง
POST /api/auth/register Public ลงทะเบียนผู้ใช้ทั่วไป (Adopter)
POST /api/auth/login Public เข้าสู่ระบบผู้ใช้ทั่วไป เพื่อรับ USER_TOKEN
POST /api/upload Authenticated อัปโหลดภาพสัตว์เลี้ยงเข้า Storage Bucket pet-images
GET / POST /api/shelters Public / ADMIN ดูรายชื่อ / สร้างศูนย์พักพิงสัตว์แห่งใหม่
PUT / DELETE /api/shelters/:id ADMIN แก้ไข / ลบข้อมูลศูนย์พักพิงสัตว์
GET / POST /api/categories Public / ADMIN ดูรายชื่อ / สร้างหมวดหมู่ชนิดสัตว์เลี้ยง
GET / POST /api/pets Public / STAFF, ADMIN ค้นหาสัตว์พร้อมตัวกรอง / ลงทะเบียนสัตว์หาบ้าน
POST /api/pets/:id/inquiries Authenticated ผู้สนใจส่งคำถามเกี่ยวกับสัตว์เลี้ยงตัวนั้น
POST /api/applications ADOPTER ยื่นใบสมัครขอรับอุปการะสัตว์เลี้ยง
PATCH /api/applications/:id/status STAFF, ADMIN อนุมัติ / ปฏิเสธคำขอ (อัปเดตสถานะสัตว์เป็น ADOPTED)
🧪 ลำดับขั้นตอนการกดทดสอบในไฟล์ api.http
1 เข้าสู่ระบบแอดมิน (Admin Login) และบันทึก Token
POST /admin/login
  1. เปิดไฟล์ api.http ใน VS Code เลื่อนไปที่หัวข้อ 1.1 Admin Login
  2. คลิกข้อความสีฟ้า Send Request เหนือบรรทัด POST http://localhost:9091/admin/login
  3. หน้าต่างฝั่งขวาจะแสดงผลลัพธ์ตอบกลับ (Response 200 OK): 
    {
  "message": "Admin login successful",
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": { "role": "ADMIN" }
}
  4. ให้ทำการ Copy ค่าตัวอักษรในฟิลด์ "token" (ไม่รวมเครื่องหมายคำพูด)
  5. เปิดไฟล์ .env แล้วนำไปวางต่อท้ายบรรทัด: 
    ADMIN_TOKEN=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
    *(กดบันทึกไฟล์ Ctrl + S)*
  6. กลับมาที่ api.http คลิก Send Request ที่ 1.2 Admin Profile เพื่อทดสอบการยืนยันตัวตนแอดมิน
2 สมัครและล็อกอินบัญชีผู้ขอรับเลี้ยง (User Signup & Login)
POST /api/auth/login
  1. คลิก Send Request ที่ 2.1 User Signup เพื่อลงทะเบียนผู้ใช้ทั่วไป (Adopter)
  2. คลิก Send Request ที่ 2.2 User Login เพื่อล็อกอิน
  3. Copy ค่า "token" ของ User จากผลลัพธ์ แล้วนำไปวางในไฟล์ .env ที่ตัวแปร: 
    USER_TOKEN=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
    *(กดบันทึกไฟล์ Ctrl + S)*
  4. คลิก Send Request ที่ 2.4 User Profile เพื่อตรวจสอบข้อมูลโปรไฟล์ส่วนตัว
3 อัปโหลดภาพสัตว์เลี้ยงเข้า Storage Bucket (Upload Image)
POST /api/upload
  • เลื่อนไปที่หัวข้อ 2.5 Upload Pet Image แล้วคลิก Send Request
  • ระบบจะส่งภาพ top.png ขึ้น Supabase Storage Bucket pet-images ผ่าน Multer และส่งผลลัพธ์กลับมา: 
    {
  "message": "Image uploaded successfully to Supabase Storage",
  "imageUrl": "https://bhothshcvbmpeajweypw.supabase.co/storage/v1/object/public/pet-images/uploads/pet-...",
  "path": "uploads/pet-..."
}
  • URL นี้จะถูกนำไปใช้เป็นรูปภาพของสัตว์เลี้ยงในการทดสอบขั้นตอนถัดไป
4 ทดสอบ CRUD ศูนย์พักพิง (Shelters) & หมวดหมู่ (Categories)
CRUD
  1. หมวดหมู่ศูนย์พักพิงสัตว์ (Shelters):
    • คลิก 3.1.1 Get all Shelters เพื่อดึงศูนย์พักพิงทั้งหมด
    • Copy ค่า "id" ของศูนย์พักพิงแห่งแรกที่แสดง นำไปวางใน .env ที่ตัวแปร: 
      SHELTER_ID=c3f15c7a-9817-47be-a567-c12140bb7a79
    • ทดสอบยิง 3.1.2 Create Shelter (สร้างศูนย์พักพิงใหม่)
    • ทดสอบยิง 3.1.3 Get Shelter by ID และ 3.1.4 Update Shelter
  2. หมวดหมู่ชนิดสัตว์ (Categories):
    • คลิก 3.2.1 Get all Categories แล้ว Copy ค่า "id" ไปใส่ใน .env ที่: 
      CATEGORY_ID=11111111-1111-1111-1111-111111111111
    • ทดสอบยิง 3.2.2 Create Category (สร้างหมวด Hamster)
    • ทดสอบยิง 3.2.3 Get Category by ID และ 3.2.4 Update Category
5 ทดสอบ CRUD สัตว์เลี้ยง (Pets) และระบบสอบถาม (Inquiries)
CRUD + POST Inquiry
  1. คลิก 3.3.1 Get all Pets เพื่อดึงรายการสัตว์ที่หาบ้านทั้งหมด
  2. Copy ค่า "id" ของสัตว์ตัวที่ต้องการ นำไปวางใน .env ที่ตัวแปร: 
    PET_ID=33333333-3333-3333-3333-333333333331
  3. คลิก 3.3.2 Create Pet เพื่อลงทะเบียนสัตว์เลี้ยงตัวใหม่ (เช่น สุนัข Corgi)
  4. คลิก 3.3.3 Get Pet by ID และ 3.3.4 Update Pet
  5. คลิก 3.3.5 Ask Question / Inquiry about Pet (จำลองผู้ใช้ทั่วไปยิงคำถามสอบถามข้อมูลเพิ่มเติมเกี่ยวกับสัตว์เลี้ยง)
6 ทดสอบระบบยื่นคำขอรับเลี้ยง (Adoption Application Workflow)
WORKFLOW
  1. คลิก 3.4.1 Submit Application (จำลอง Adopter ยื่นเอกสารขอรับเลี้ยงน้องหมา PET_ID)
  2. Copy ค่า "id" ของใบสมัครจาก Response ไปวางใน .env ที่ตัวแปร: 
    APPLICATION_ID=d890b05b-80fb-40c9-9430-c3d526fa1789
  3. คลิก 3.4.2 Get Applications (ผู้ใช้ดูรายการคำขอของตนเอง)
  4. คลิก 3.4.3 Get Application by ID เพื่อดูรายละเอียดคำขอ
  5. คลิก 3.4.4 Review Application (แอดมินกดอนุมัติเป็น APPROVED)
    *จุดเด่น:* ระบบจะทำการเปลี่ยนสถานะของสัตว์เลี้ยงตัวนั้นให้เป็น ADOPTED ในฐานข้อมูลโดยอัตโนมัติ
7 ตรวจสอบผลงานผ่านหน้าเว็บ Web Content Manager (Admin UI)
UI DASHBOARD

เปิด Google Chrome หรือ Browser แล้วพิมพ์เข้าไปที่:

👉 http://localhost:9091/admin
  • สามารถดู Dashboard สรุปจำนวนสัตว์เลี้ยง, หมวดหมู่, ศูนย์พักพิง และสถานะการยื่นคำขอรับเลี้ยง
  • มีฟังก์ชันทดสอบสดในรูปแบบหน้าเว็บ สไตล์ Strapi Dark Mode Content Manager
